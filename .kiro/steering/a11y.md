# Web 无障碍工程基线

本项目以 WCAG 2.2 AA 为目标。Kiro 在需求、设计、实现和评审中均应应用以下规则。

## 1. 按“谁提供对错标准”分层

- **A — 通用规则**：规则由标准或工具提供。使用 axe-core、语义查询和静态检查验证。
- **B — 页面行为**：正确结果由产品团队提供。先询问页面预期，再生成 Playwright 行为测试。
- **C — 真实体验**：正确性依赖业务语境。AI只能提出候选判断，必须保留人工与辅助技术验证。

## 2. 证据要求

- A层：保留扫描报告和修复后的回归结果。
- B层：使用真实浏览器验证 Tab/Shift+Tab、焦点进入与恢复、键盘陷阱和动态状态。
- C层：记录 VoiceOver 实际播报及人工判断；不得用自动化绿灯替代体验结论。

## 3. 澄清规则

遇到以下信息不完整时，先提问，不要自行假设：

- 页面特有的正确焦点顺序；
- 对话框打开后的初始焦点；
- 图表、趋势和状态需要传达的业务含义；
- 哪些页面、角色和交互状态属于本次范围。

## 4. 实现规则

- 信息不得只依赖颜色、形状或位置表达。
- 所有交互控件必须具有可访问名称并可使用键盘操作。
- 动态内容应提供可被辅助技术感知的状态。
- 修复必须附带最小回归测试；新发现的通用问题应回填本文件或共享组件规范。
- 不得声称自动化测试全绿等于满足全部无障碍要求。

## 5. 组件规则

- 下拉选择框（MUI `TextField select`）的名称需绑定到 `combobox` 节点（使用 `label` 或 `slotProps.select` 传入），不要把 `aria-label` 放在根 `div`（axe `aria-input-field-name`）。
- MUI `LinearProgress` 必须提供 `aria-label` 或 `aria-labelledby`（axe `aria-progressbar-name`）。
- `IconButton` 必须提供 `aria-label`（axe `button-name`）。
- 表达趋势方向的图标设置 `aria-hidden="true"`，方向以可见文字（如“上升 / 下降”）表达。
